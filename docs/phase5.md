# 阶段 5：Report Agent

阶段 5 已完成并通过功能验收及自动化回归。报告读取已完成的阶段 4 运行目录，不修改它；只有“问题清单”和“亮点”由模型撰写，且必须通过证据门禁，其余章节全部由代码从完整记录计算。

## 执行

```powershell
.venv-browsing/Scripts/python.exe -m orchestrator.phase5 <阶段4目录> --capability-run <能力文件目录>
```

- `--capability-run` 必须指向含 `capability_profile.json` 且与当前提供商、模型、地址、协议、思考配置匹配的目录。阶段 4 原样本用 DeepSeek，而环境已切到 MiMo，所以不能沿用其审批目录里的能力文件。
- `--no-model` 只生成不需要模型的章节（问题清单与亮点为空），用于零成本检查证据索引。
- `--run-dir` 指定输出目录，必须是新目录。输出前后对来源目录的 `.db/.json/.jsonl` 做哈希比较，变化则验收失败。输出目录与来源在不同盘符时，报告链接改用绝对 `file:` URI。
- 来源的 `phase4_result.json` 未通过时仍生成报告，但覆盖说明第一条明确标出，`phase5_result.json` 记录 `source_phase4_passed=false`。

## 证据索引（`report/evidence.py`）

以只读方式（`mode=ro`、`query_only`）打开 `run.db` 和 `community/oasis.db`，并重新校验：体验文件与数据库一致、截图哈希、技术事件存在、问卷引用、表达决定引用的结论存在。任何不一致直接报错而不是跳过。记录分七类：`experience`、`withheld`、`discussion`、`reads`、`surveys`、`media`、`coverage`。点赞数不进入索引。

一条结论是否算“已公开”，以 `actions` 表中平台实际接受的发帖/评论为准（`shared` 只是意图，平台可能拒绝）。

## 证据门禁（`report/agent.py`）

模型结论（`Claim`）逐条检查，任何一条不满足即退回：

1. 至少一条引用；每个 `ref_id` 必须存在于索引。
2. 每条 `quote`（≥3 字）必须是被引记录中某个字符串字段的原文子串。
3. `issues` 至少引用一条 `kind=pain` 的体验结论，`highlights` 引用 `kind=highlight`；引用了相反类型的结论也退回。
4. 标题和正文点名的 Persona 都必须引用其本人与章节同类型的体验结论，防止正文声称“多人受影响”而证据只有一两人。

退回的结论不进报告，记入 `rejected_claims`。

**排序**：`影响人数 × 严重度 × 证据强度`。影响人数 = 被引的、与章节同类型（pain/highlight）的体验结论所属的不同 Persona 数；其他被引记录（步骤、截图、问卷、帖子等）只作为佐证，不增加人数，避免引用 `pXX:outcome` 之类的无关记录抬高排序；证据强度 = 1 + 0.5（有截图）+ 0.5（有技术事件），带“页面结构被丢弃”标记时减半。社区点赞不参与。

## ReACT 循环

每步模型返回一个 JSON：`query`（按类别和 Persona 分页读取证据，每页 ≤30）或 `final`（给出结论）。提示词一开始就带有全部体验结论目录（编号、类型、标题、原文前 80 字），所以通常无需查询。工具调用走 JSON 而不是原生 tool calling，因为 Responses 协议的消息桥接不支持工具结果消息，而 JSON Object 在两种协议上都可用。`final` 被门禁退回时，退回原因作为观察反馈，最多修复 2 轮；总轮数上限 10，最后一轮强制 `final`。

## 报告结构

| 章节 | 来源 |
|---|---|
| 总览：任务结果、NPS、继续使用/付费、覆盖说明 | 代码 |
| 问题清单、亮点 | 模型，经证据门禁 |
| 公开声音（帖子/评论原文，不含点赞） | 代码 |
| 沉默信号（每条结论一行，列出全部隐瞒理由；潜水者、点赞者、从未公开者、问卷自述未说出口） | 代码 |
| 公开讨论与私下问卷一致性（保留阶段 4 的复核标记） | 代码 |
| 舆论动态（体验前/后看帖数、自述观点改变及其帖子、触达量） | 代码 |
| 分时段体验差异（按本地浏览时段汇总结果与情绪均值） | 代码 |
| Scout 不一致 | 恒为“未执行”，不编造 |

每个结论条目都带 `ref_id`；`verify_report` 检查它们全部可解析，否则验收失败。时段中没有已校验体验的 Persona 引用其人设记录，缺体验不会导致验收失败（已在覆盖说明中列出）。问题与亮点另附原文、`experience.json` 路径、截图链接、Steel 回放链接（含估算的视频秒数，偏移基准写在记录里，非精确）和技术事件编号。

覆盖说明固定包含：服务端时间无法模拟；Scout 未执行；样本是合成 Persona；任务成败主要来自 Agent 自述；公开文字是阶段 4 的模板化投影。按数据追加：无体验的 Persona、缺少问卷的 Persona、晚验证的体验、问卷补录目录（可能混用模型）、评估被退回、页面结构被丢弃的步骤数、社交审计未通过、规划器退回不行动次数。

## 已知限制

- “影响人数”依赖模型把同一问题的各人证据都引全；门禁只能保证引了的都真实、正文提到的都有引用，不能保证没有遗漏的人。
- 沉默信号以“本人该次表达决定”为准；他人是否公开过相同内容不判断。
- 回放链接的视频秒数基于 Steel `created_at` 与本地时钟估算。
- Scout 仍未执行；采访与 Web UI 属于阶段 6。
