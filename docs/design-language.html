Design Language · for builders & agents

像观察室一样冷静，
像研究笔记一样可追溯。

muchhuman 让模拟人物真实使用产品、在社区里讨论，最后给出附带证据的结论。界面的任务是：让人信任结论，并且随时能核对结论。

本文档只规定“怎么设计、怎么交互”，不规定具体页面。任何 Agent 在设计或实现 muchhuman 的界面前，都必须先读完本文档。

01如何使用本文档

本文档面向设计和实现界面的 Agent 与开发者。规则按强度分为三级：

措辞含义
必须 / 禁止硬性规则，违反就视为缺陷。
应该 / 不应默认做法。偏离时要在交付说明中写明理由。
可以允许的做法，由设计者自行判断。
  • 颜色、字号、间距、圆角、阴影必须使用第 16 节的设计令牌（CSS 变量），禁止在组件里写死色值。
  • 本文档中的组件样例就是规范本身：实现时应在视觉上与样例保持一致。
  • 遇到本文档没有覆盖的情况，按第 02 节的设计原则推导；仍然无法确定时，选更简单、更克制的方案。

02设计原则

以下六条原则按优先级排列。原则之间冲突时，排在前面的优先。

1

证据优先

每条结论都必须能在三次点击内追到原始证据：步骤、截图、报错、录像时间点。没有证据的结论不展示，或者明确标注为“无证据”。

2

区分说出来的与没说出来的

公开发言、体验了但没说出来的、私下问卷，是三种不同的信息。它们在视觉上必须始终可以区分，不能混在一起展示。

3

人物是人，但必须标明是模拟

人物要有名字、性格和作息，让人有代入感。但任何地方都不能让人误以为他们是真实用户：使用抽象头像，并带上“模拟”标识。

4

时间是一个维度

模拟时间和真实时间必须一眼就能分清。凡是和“什么时候发生”有关的内容，都应该能在时间轴上定位。

5

冷静的仪器

界面像一台仪器，而不是营销页。少用装饰，克制用色，颜色只用来表达含义。数据是主角。

6

花钱的操作必须透明

每次运行都会消耗模型调用和云端浏览器费用。触发开销的操作必须先告诉用户预估的花费和耗时，运行过程中可以随时暂停或取消。

03语气与文案

界面使用简体中文，语气像一位严谨的研究员：陈述事实，标明来源，不夸张，也不卖萌。

文案规则

  • 先说结论，再给依据。例如：“7 人中有 4 人没能完成注册 · 证据 12 条”。
  • 数字要具体。写“4/7 人”，不要写“多数用户”。百分比必须同时给出分母。
  • 引用人物的话时，必须标注是谁、在什么模拟时间说的，并保留原话语气，不要润色。
  • 不要把模拟结果写成事实。写“模拟中 4 人受阻”，不要写“用户无法注册”。
  • 错误提示要说清三件事：发生了什么、影响范围、下一步怎么办。
  • 中文与英文、数字之间加一个空格。中文语境使用全角标点。
  • 按钮用“动词 + 名词”，例如“开始运行”“查看证据”，不要用“确定”“好的”。

04色彩

底色是暖中性的纸色，主色只有一个蓝色。其余颜色都是语义色，每种颜色只对应一种含义。禁止把语义色用作装饰。

中性色与主色

背景--bg
表面--surface
次级表面--surface-2
正文--text
主色 · 可操作--accent
  • 主色 --accent 只用于可以点击或操作的元素：主按钮、链接、证据标签、焦点框、选中状态。不可点击的元素不得使用主色。
  • 文字分为三级：--text 用于正文，--text-2 用于说明，--text-3 用于辅助信息。不要再引入第四级灰色。

05字体与排版

正文用系统中文无衬线字体，所有机器数据用等宽字体。用字号和字重建立层级，不用颜色。

  • 数字列必须右对齐，并使用 font-variant-numeric: tabular-nums。
  • 正文每行最长约 40 个汉字（约 760px）。
  • 人物的发言引用保留原文，用 --text 显示；系统的转述用 --text-2 显示，两者要能区分开。

06间距、圆角、层级

间距 · 4px 栅格

组件内部用 4、8、12；组件之间用 16、24；区块之间用 48、64。禁止使用栅格以外的数值。

圆角

标签和小控件用 4，按钮和输入框用 8，卡片和面板用 12，头像和胶囊标签用全圆。

层级

层级优先用边框区分，阴影只给浮层使用：--shadow-1 用于悬停卡片，--shadow-2 用于抽屉、弹窗和下拉菜单。

布局

  • 以桌面为主（这是一个分析工具），设计基准宽度为 1440。内容区最大宽度 1280，超出部分两侧留白。
  • 三栏结构：左侧导航 240，中间主区域自适应，右侧证据抽屉 480。抽屉从右侧滑入，不遮挡主区域的关键数据。
  • 信息密度为中高。表格行高 40，紧凑模式下 32。

07图标与头像

  • 图标统一使用线性风格（推荐 Lucide），线宽 1.5，尺寸为 16 或 20。禁止混用面性和线性两种风格。
  • 只有通用图标（如设置、关闭、搜索）可以单独出现，不配文字；其余图标都必须配文字或 tooltip。
  • 人物头像必须是抽象的：人物色圆底加姓名首字。禁止使用写实人像或 AI 生成的人脸照片，避免让人误以为是真实的人。
  • 潜水者的头像用虚线描边、空心底，表示“在场但没有发言”。

  • 全局只有一条时间轴，表示模拟时间。夜间（00–06、23–24）用次级表面色做底，用来暗示作息。

8.5 模拟时间与真实时间

应该

  • 模拟时间：◷ D1 21:10，紫色等宽胶囊，带时钟符号
  • 真实时间：2026-10-02 14:03:22，灰色等宽，不加底色
  • 同一处需要同时显示时，模拟时间放在前面

不应

  • 用同一种样式显示两种时间
  • 模拟时间不写“D1”这样的天数前缀
  • 用相对时间（如“3 分钟前”）表示模拟时间

09基础组件

按钮

  • 每个视图最多一个主按钮。
  • 会产生费用的按钮，必须在按钮上直接显示预估的费用和耗时。
  • 危险操作（终止运行、删除运行）使用描边红色样式，并且必须二次确认（见第 12 节）。
  • 按钮高度为 32，紧凑模式为 28。按钮文字不换行。

标签、状态

等待中 体验中 在社区 已完成 已放弃 出错
  • 人物运行状态只有这六种，必须使用上面的样式。“已放弃”是正常的模拟结果，不是错误，禁止用红色表示。

10交互原则

A

逐层展开，不跳页

从总览到发现、从发现到证据、再到录像片段，全部在当前页面内通过抽屉逐层展开，用户始终不会丢失上下文。

B

一切都可以点

人物、时间、证据、帖子都是可以点击的对象，点击后打开它的详情。看到一个名字却点不开，视为缺陷。

C

机器在跑时，人能看到并且能控制

运行过程中实时显示每个人物的状态、当前的模拟时间和已经花掉的费用。可以随时暂停、继续或终止。

D

先确认，再花钱

所有会产生费用的操作，都要先经过一个能看到预估费用的确认步骤。之后的结果中，再显示实际花费。

E

AI 生成的内容可以修改

主 Agent 生成的人物、作息和配置都是草稿：用户可以修改、删除、重新生成。修改过的地方要标出来。

F

键盘可以完成所有操作

Esc 关闭抽屉，J / K 切换上一条或下一条，/ 进入搜索，空格播放或暂停时间轴。

11关键交互模式

11.1 证据链（三次点击到达原始证据）

L0总览

关键数字和排序后的发现列表

L1发现

现象、受影响的人物、证据标签

L2证据抽屉

步骤、截图、轨迹，以及当时的情绪

L3录像片段

自动定位到对应时间点，前后各留 5 秒

  • 证据抽屉里必须同时显示：人物标签、模拟时间、步骤编号、URL、截图，以及该人物在这一步的观察权限（例如“该人物看不到 Console”）。
  • 如果一条证据被多条发现引用，要在抽屉中反向列出所有引用了它的发现。

11.2 运行前审核

审核关卡样例
10 个人物 · 模拟 1 天 · 6 条关键流程
⚠ 说明书中的“导出报表”入口在侦察时没有找到，已经记为一条发现。
预估费用¥32–45
预估耗时20–30 分钟
模型调用≈ 640
  • 审核页面必须依次展示：人物列表（可编辑）、作息时间表（时间轴视图）、覆盖情况检查（每个关键流程由几个人负责、各种参与方式的分布）、侦察时发现的问题、费用和耗时预估。
  • 覆盖情况不满足要求时（例如某个流程少于 2 人），在对应位置显示困惑色的提醒，但不阻止运行。
  • 用户修改过的人物显示“已修改”标记，可以一键恢复成主 Agent 的原始版本。

11.3 运行中

  • 页面顶部固定一条运行状态栏：模拟时钟、整体进度、已花费用、暂停和终止按钮。切换到其他页面后，状态栏依然保持在顶部。
  • 人物列表实时更新状态。点击正在体验中的人物，可以看到他的实时画面（Steel 的实时视图），并以只读的“围观”模式观看。
  • 社区动态以信息流的形式实时追加。新内容出现时不自动滚动，只显示“有 n 条新动态”的提示。

11.4 时间联动

  • 选中一个模拟时刻后：社区视图显示到该时刻为止的帖子，人物状态回到该时刻，证据列表过滤到该时刻之前。
  • 当前选中的时刻要同步到 URL 参数中，方便分享和回到同一位置。

11.5 采访

  • 采访使用对话界面，顶部固定显示人物卡和“模拟人物”的提示。
  • 人物的回答如果引用了自己的体验，要附上证据标签。
  • 当人物在回答中回避问题时（属于未说出的行为），界面不做额外提示，保持人物本身的真实表现。可以提供一个按钮，打开该人物的完整体验记录作为对照。

12状态与反馈

状态规则
空状态说明这里会出现什么内容，并给出产生内容的下一步操作，例如“上传使用说明，开始第一次运行”。不使用插画。
加载300ms 以内不显示任何加载提示；超过 300ms 显示骨架屏；预计超过 10 秒的任务显示进度和剩余时间。
错误说明发生了什么、影响了哪些人物或步骤、是否可以重试，同时给出技术详情（可以折叠）。单个人物出错不应中断整个运行。
部分完成报告中显式列出缺失的部分，例如“2 名人物因为出错没有完成体验，他们的数据不计入统计”。
确认标题写清后果，例如“终止运行？已经产生的 ¥12.4 费用不会退回”。确认按钮重复具体的动作，例如“终止运行”。
成功轻量提示，3 秒后自动消失。如果有后续操作，在提示中直接给出入口。

13数据可视化

  • 人数优先用点阵或分数表示，少用百分比：例如“●●●●○○○ 4/7”。样本只有 10 个人，百分比会显得结论比实际更有把握。
  • 情绪曲线：横轴是步骤，纵轴从受挫到满意，零线居中；困惑程度用点的大小表示。点击某一点，打开该步骤的证据。
  • 系列颜色：按人物区分时用人物色，按语义区分时用语义色，两者禁止在同一张图中混用。
  • 图表必须有标题、坐标轴单位和数据来源（例如“来源：体验记录 · 7 名人物”）。
  • 不使用 3D 图、饼图（类别超过 3 个时）和双纵轴图。
  • 每张图都要能切换成表格形式，方便核对数据。

14动效

  • 动效只用来表达状态变化和空间关系（例如抽屉从哪个方向出现），不做装饰性动画。
  • 时长：悬停 120ms，展开或切换 200ms，抽屉 320ms。统一使用缓动曲线 --ease。
  • 只有“体验中”和“在社区”这两种状态使用呼吸动画，表示人物正在活动。
  • 必须遵守 prefers-reduced-motion：用户开启“减少动态效果”后，关闭呼吸动画和位移动画。

15可访问性与响应式

  • 正文与背景的对比度不低于 4.5:1，大字和图形不低于 3:1，浅色和深色主题都要满足。
  • 不能只用颜色传达信息：严重度要配文字，可见性要配边框样式和文字，状态要配文字。
  • 所有可交互元素都要有可见的焦点框（2px 主色，外偏移 2px）。
  • 图表要提供 aria-label 的文字摘要，以及可以切换的表格视图。
  • 必须同时支持浅色和深色主题，默认跟随系统设置，用户也可以手动切换。
  • 响应式规则：
    • ≥1280：完整的三栏布局。
    • 960–1279：左侧导航收起为图标。
    • <960：单栏布局，抽屉改为全屏打开。
    • 手机端只需要支持查看报告和运行状态，不需要支持配置和审核。
    • 页面左右边距 16，任何宽度下都禁止出现横向滚动。

16设计令牌

下面是本文档 <style> 中 :root 块的摘要，完整内容（包括深色主题）以源码为准。实现时直接复制源码中的这一块。

:root {
  /* 中性 */  --bg --surface --surface-2 --border --border-strong --text --text-2 --text-3
  /* 主色 */  --accent --accent-hover --accent-soft --on-accent
  /* 模拟时间 */ --sim --sim-soft
  /* 严重度 */ --sev-1 --sev-2 --sev-3 --sev-4
  /* 情绪 */  --pos --pos-soft --neg --neg-soft --confused --confused-soft
  /* 可见性 */ --vis-public --vis-withheld --vis-withheld-soft --vis-private --vis-private-soft --hatch
  /* 人物 */  --p1 … --p10
  /* 字体 */  --font-sans --font-mono
  /* 字号 */  --fs-xs 12 · --fs-sm 13 · --fs-md 14 · --fs-lg 16 · --fs-xl 20 · --fs-2xl 24 · --fs-3xl 32
  /* 间距 */  --sp-1 4 · --sp-2 8 · --sp-3 12 · --sp-4 16 · --sp-5 24 · --sp-6 32 · --sp-7 48 · --sp-8 64
  /* 圆角 */  --r-sm 4 · --r-md 8 · --r-lg 12 · --r-full
  /* 阴影 */  --shadow-1 --shadow-2
  /* 动效 */  --ease · --dur-fast 120ms · --dur 200ms · --dur-slow 320ms
}
深色主题：@media (prefers-color-scheme: dark) 配合 :root:not([data-theme="light"])，以及 :root[data-theme="dark"]，两处使用同一组值。

17交付前自检清单

任何 Agent 交付界面之前，都要逐条检查以下各项，并在交付说明中列出不满足的项及理由。

  • 所有颜色、字号、间距、圆角都来自设计令牌，没有写死的数值。
  • 每条结论都能在三次点击内到达原始证据；没有证据的结论有明确标注。
  • 说出的、未说出的、私下的三种内容，在颜色、边框和文字上都能区分；社区视图中没有出现未说出的内容。
  • 每个人物都显示了“模拟”标识，头像是抽象的，人物色在各个视图中保持一致。
  • 模拟时间和真实时间使用了各自的样式。
  • 会产生费用的操作显示了预估费用，并经过确认。
  • “已放弃”状态没有用红色表示，单个人物出错不会中断整个运行。
  • 人数使用“x/y”的形式，没有单独出现的百分比。
  • 不只靠颜色传达信息；对比度达标；焦点框可见；键盘可以完成所有操作。
  • 浅色和深色主题都检查过，在 375px 宽度下没有横向滚动。
  • 文案符合第 03 节：术语统一，先说结论，数字具体，没有把模拟结果写成事实。
